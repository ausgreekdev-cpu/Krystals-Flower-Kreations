## LLM (procedure analysis + document enrichment)

- `backend/src/services/llm.js` is the single provider-agnostic transport (JSON-in/JSON-out). Providers: `anthropic` (default) | `openai` | `opencode-go` | `gemini`.
- `LLM_PROVIDER` picks the provider; `LLM_API_KEY` is the key — the **gemini** provider also accepts `GEMINI_API_KEY` (Google AI Studio key, `https://aistudio.googleapis.com` shape: `AIza…`). `LLM_MODEL` overrides the model (defaults: `claude-3-5-haiku-latest` / `gpt-4o-mini` / `mimo-v2.6-flash` / `gemini-3.1-flash-lite`); `LLM_BASE_URL` overrides the base.
- Gemini request shape: `systemInstruction` + `contents[]` + `generationConfig.responseMimeType: application/json`; key sent as the `x-goog-api-key` header. Plain `fetch` — no SDK dependency.
- **Transient throttling**: one retry after 750ms on upstream 429/503 (Gemini free tier flips 503 under demand); anything else falls back to rules immediately.
- **Custom OpenAI-compatible endpoints**: the `openai` provider now honours `LLM_BASE_URL` (it used to be hardcoded to api.openai.com), so Gemini's compat surface works as a drop-in: `LLM_PROVIDER=openai` + `LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai` + `LLM_MODEL=gemini-3-flash-preview` + `LLM_API_KEY=<key>`.
- **No key = no LLM**: `llmAvailable()` is false, and `procedureAnalyzer` falls back to its rules engine (still works, less rich) — same for `documentEnricher` (returns null).
- Keys are **server-side env only** — never a setting in the DB and never in the frontend. Prod keys live in the Netlify env (see `.env.netlify.template`); local ones in `backend/.env` (gitignored).
- Tests stub the transport (`__setLlmCall` in `lib/llm.js` consumers) or `globalThis.fetch` — the suite never calls a provider. **Hard guarantee**: `llmAvailable()` returns false whenever `NODE_ENV=test` (only the `__setLlmCall` stub counts there), so a real key on disk can never leak a network call into `npm test`.

## Gotchas

- **`npm install` needs `--no-audit` when rebuilding the tree** — the audit step can't resolve backend's CDN-only `xlsx@0.20.3` from the registry and aborts the whole install with ETARGET. Also use `npm_config_maxsockets=1` when installs stall.
- **npm 10 overrides quirk**: flat `overrides` entries are silently ignored for workspace-member subtrees — only the nested form works: `"express": {"qs": "6.16.1"}`. After changing overrides, a FULL clean (`rm -rf node_modules package-lock.json`) is required or the stale tree wins; re-run `npx prisma generate` from `backend/` afterwards.
- **Secret files on disk are gitignored, not safe**: `stripe_backup_code.txt`, `docs/proton_2FA_recovery_codes.txt` (and `*backup_code*`, `*recovery_codes*` patterns) live in the working tree — move them out of the repo and rotate the credentials; .gitignore only stops commits.
- **DB backups**: `scripts/db-backup.sh` dumps prod (Supabase `DIRECT_URL`) to `backups/` via `pg_dump` (needs postgresql-client) — run it on a cron; Supabase Free has no automatic backups.

- **Prisma CLI ignores inline `DATABASE_URL`** — the CLI loads `backend/.env` and that value WINS over the shell env (a bogus inline URL still connects to localhost). To push to prod: temporarily point `backend/.env`'s `DATABASE_URL`/`DIRECT_URL` at the supabase values from `.env.supabase`, run `npx prisma db push`, then **restore `.env` immediately**. (`npx prisma db pull --print` output can lie for the same reason — verify prod state with `information_schema`/`pg_indexes` via a PrismaClient script, which does honor an explicit `datasources.url`.)
- **Booking-creating tests** (`hardening`, `security`, `settingsBehaviour`) must call `cleanupTestBookings()` from `test/helpers.js` in both `before()` and `after()` — otherwise `bookedCount` accumulates until every session is full and capacity assertions fail on repeat runs.
- **Restart the API after route edits** — `node --watch` or a stale server causes false 404s. Kill by pid (`kill <pid>`, not `pkill -f`, which can kill the shell wrapper).
- Avoid shell variable `UID` (readonly in bash).
- **Zod**: `z.enum().strict()` is invalid; `.refine()` result has no `.partial()` (validate the base schema then refine).
- **Prisma**: upsert rejects `null` in nullable `@@unique` members → use `findFirst` + create/update. `StockMovement` has no `variant` relation.
- **PgBouncer (prod :6543)**: interactive `prisma.$transaction(async tx => …)` is incompatible. Use the batch (array) form or sequential ops. Never `.catch(()=>{})` inside a transaction (Postgres aborts the whole tx regardless).
- **Money** is `Decimal(10,2)` for commerce; wrap `Number()` around Decimal values before arithmetic.
- **Soft deletes**: Product/Discount/Collection use `deletedAt` (filter `deletedAt: null` in lists) — never hard-delete these.
- **Audit**: write admin/money actions via `lib/audit.js` (AuditLog table).
- **Email**: queue via `services/email.js` (`enqueueEmail` awaited in routes, `drainEmailQueue` in the hourly job). Transport is chosen per send in `services/emailProvider.js` — first key present wins: `RESEND_API_KEY` → `POSTMARK_SERVER_TOKEN` → `SENDGRID_API_KEY` → SMTP (`SMTP_HOST`+`SMTP_USER`+`SMTP_PASS`, lazy-required nodemailer, local/relay fallback). All API providers are plain `fetch` (no SDKs, nothing new for netlify.toml). Values that are Netlify placeholders (`...`) count as unset. Nothing configured → rows mark `failed`/`Email provider not configured`. Provider 4xx (bad key, unverified sender) fails the row immediately; 429/5xx/network stay `pending` for the next drain. Sender = `EMAIL_FROM` → SMTP login → `orders@krystalsflowercreations.com.au`; that domain must be verified with the provider. `POST /api/settings/test-email` reports `provider`/`from` and sends for real.
- **Installs / locks**: the root `package-lock.json` is the only lock for backend+frontend (mobile keeps its own for standalone Expo). Never create `backend/package-lock.json`/`frontend/package-lock.json` (e.g. `npm install --prefix …` does) — a second lock forks a divergent tree. Install from the repo root (`npm ci --workspace=backend --workspace=frontend --include=dev`); member-dir installs are OK since npm walks up.
- **Adding a setting**: one entry in `backend/src/lib/settingsSchema.js` (SECTIONS/SETTINGS). Validation, public filter, defaults and the admin form (`GET /api/settings/schema`) all derive from it — never hand-edit the admin form. Endpoints: public `GET /api/settings`, admin `GET /api/settings/all|schema`, `PUT /api/settings` (validated upsert), `POST /api/settings/reset` `{keys}` (drops overrides → defaults), `POST /api/settings/test-email` `{to}` (reports `smtpConfigured`). Storefront reads them through `frontend/src/lib/publicSettings.js` (`usePublicSettings()`); after a save the admin form re-applies the theme (`applyTheme({force:true})`) and invalidates that cache. Settings are **global DB state**: tests that flip them must restore defaults in their `after()` hook so they can't leak into other suites.

## Cart recovery (abandoned-cart reminders)

- **Capture** — `Cart` gained `email`/`emailCapturedAt`/`reminderSentAt` (schema.prisma; `db push`, no migrations dir). `POST /api/cart/email` (`routes/cart.js`, zod `{cartId, email}`, rate-limited 10/min, 404 unknown cart) stores the lowercased email. Two callers: (1) Cart page "Email me a reminder" field (`Cart.jsx`, fire-and-forget `cartApi.saveEmail`); (2) Checkout.jsx debounced 800ms effect on `form.email` — catches PayPal-window abandons (order never created, email never submitted). The endpoint does NOT `touchCart` — the idle clock keeps reflecting last shopping activity.
- **Detection/send** — `services/cartRecovery.js` `runAbandonedCartReminders(settings)`: eligible = `email != null && reminderSentAt == null && updatedAt <= now-idleHours && items some {}`, `take: 20`. Idle hours = `min(abandoned_cart_reminder_hours, cart_retention_hours − 1)` (clamp so a cart is never emailed about to be hard-deleted). Sends `sendCartReminder` (email.js, template `cart_reminder` — itemised lines, subtotal, `${FRONTEND_URL}/cart?restore=<cartId>`, retention note, "ignore this email" line), then stamps `reminderSentAt`.
